# MiniSig

最小のマルチシグウォレット。**教材用**であり、実運用には [Safe](https://safe.global) を使うこと。

Base Sepolia 上で実際に動いている。操作画面と API は別リポジトリ
[minisig-app](https://github.com/nakamura196/minisig-app) にある。

## 仕組み

`src/MiniSig.sol`、約 140 行。やっていることは3つだけ。

1. 所有者リストと閾値を持つ
2. 「これから実行する取引」を一意なハッシュにする
3. そのハッシュへの署名を閾値の数だけ検証し、通れば実行する

**秘密鍵はどこにも渡らない。** 所有者は取引のハッシュに署名し、コントラクトは
`ecrecover` で署名から署名者を逆算して、所有者リストと照合する。

### 実装上のポイント

- **nonce** — 同じ署名の使い回しを防ぐ。実行の**前**に増やすので再入しても通らない
- **ハッシュに `chainid` と自分のアドレスを混ぜる** — 別チェーン・別コントラクトへ署名を流用できない
- **署名者アドレスの昇順を強制** — マッピングを持たずに重複を排除する。同じ人が
  2回署名しても2人分にはならない。Safe も同じ方式
- **`onlySelf`** — 所有者の追加・削除・閾値変更は `execTransaction` 経由でしか呼べない。
  つまり変更にも閾値ぶんの署名が要る。**外部の管理者は存在しない**

## テスト

```
forge test
```

17件。守っているのは次のとおり。

| | |
|---|---|
| 2本の署名で実行できる | 正常系 |
| **1本では実行できない** | マルチシグの本体 |
| 同じ署名を使い回せない | nonce |
| 所有者でない者の署名は通らない | `isOwner` 照合 |
| **同じ人が2回署名しても2人分にならない** | 昇順の強制 |
| 金額を書き換えると署名が無効になる | ハッシュに value が入る |
| **別コントラクトへ署名を流用できない** | ハッシュに chainid と自身のアドレス |
| 外から直接 `addOwner` を呼べない | `onlySelf`。所有者本人でも不可 |
| 2/3 の決議で4人目を追加できる | 自己統治 |
| 追加された所有者の署名が有効になる | |
| 所有者数を超える閾値は設定できない | **金庫の永久ロック防止** |

## 動かす

### ローカル（anvil）

```
anvil --port 8555          # 別の端末で
./script/demo_anvil.zsh
```

デプロイから 2/3 署名での実行までを一気に通し、最後に「署名1本では拒否される」ことも確認する。
**anvil が公開している既定の鍵しか使わない。** 本物の鍵は登場しない。

### Base Sepolia

```
KEYS=/path/to/keys.env ./script/deploy_sepolia.zsh
```

鍵ファイルはリポジトリに置かない。testnet 専用の使い捨てを別の場所に用意する。
本番では Foundry の暗号化キーストア（`cast wallet import`）を使うこと。

## 引っかかったところ

- **`forge create --constructor-args` は可変長引数。** 後ろに `--json` を置くと
  引数として飲み込まれ、`expected 2 but got 3` で落ちる。フラグは前に置く
- **`vm.expectRevert()` は直後の外部呼び出しに効く。** 引数の中でヘルパーを呼ぶと、
  その中の `view` 呼び出しに食われて「revert しなかった」と誤判定される。
  署名の生成は `expectRevert` より前に出す
- **公開 RPC はノード間で nonce の見え方がずれる。** `nonce too low` が出たらリトライする
