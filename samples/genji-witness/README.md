# genji-witness

[校異源氏物語](https://kouigenjimonogatari.github.io/) の TEI 本文
**54 帖 / 25,065 行**を素材に、Merkle ツリーとチェーンで何ができて何ができないかを
確かめる試作です。依存パッケージはゼロ (Node 標準の `crypto` と `fetch` のみ)、
コントラクトは Foundry で書いています。

```bash
node scripts/00-selftest.mjs      # 48 件。RFC 6962・IPFS・lxml・RLP・RFC 6979・cast との突き合わせ
./scripts/dev.zsh                 # anvil を立てて CorpusAnchor を配置 (起動したままにする)
node scripts/01-digest.mjs        # 54 帖と 25,065 行から 2 本の root を作る
node scripts/02-anchor.mjs        # root を刻む (公開者 + 第三者 2 人)
node scripts/03-prove.mjs 0005-01 # 1 行だけを、チェーン上で検証する
node scripts/04-permanence.mjs    # CID と Arweave の見積り (何も送信しない)
node scripts/05-compare.mjs       # チェーンが要る行だけを取り出す
cd contracts && forge test        # 27 件

./scripts/ocean-fork.zsh          # Sepolia をフォークした anvil (別の端末で起動したまま)
node scripts/06-ocean.mjs         # Ocean Protocol の本物のコントラクトに発行する
```

## 結論を先に

**1 行の版を証明するのに、チェーンは要りません。** Merkle ツリーだけで足ります。
チェーンが要るのは「その root を誰も消せない」「第三者が独立に足せる」の 2 点だけで、
しかもそれは**公開者以外の誰かが刻んだとき**に初めて意味を持ちます。

この試作でいちばん効いたのは、実はチェーンではなく Merkle ツリーの方でした。

| | 渡すもの |
|---|---|
| git で 1 行を証明する | 帖 1 本 (最大 309,169 バイト) かリポジトリ全体 |
| Merkle ツリーで 1 行を証明する | **645 バイト** (経路 480 + その行 165) |

論文で 1 行だけ引用した人に「その行が確かにこの版のものだ」と示すとき、
git は帖 1 本まるごとしか渡せません。blob の粒度がファイル単位だからです。

## 立場が逆になっている

隣の試作 [`ndl-witness`](../../ubc/ndl-witness/) では、中村は NDL の公開物を
外から観測する**第三者**でした。記録を作る人と記録される対象が別人なので、
証人として意味がありました。

校異源氏物語では、中村は**公開している側**です。記録を作る人と記録される対象が
同じになります。これは `did-prototype` (案A) が行き止まりになったのと同じ形で、
**自分で自分の版を刻むだけならチェーンは要りません** (`git tag -s` で足ります)。

だから `contracts/src/CorpusAnchor.sol` は「誰でも呼べる」を要件にしています。
`02-anchor.mjs` が公開者 1 人ではなく 3 人に刻ませるのも同じ理由です。
公開者だけが刻んだ状態では、`05-compare.mjs` は
「公開者だけ → 署名で足りる」と表示します。

## 2 本のツリー

証明したい主張が 2 通りあるので、ツリーも 2 本作ります。

| | 葉 | 葉の中身 | 主張 |
|---|---|---|---|
| 帖ツリー | 54 | ファイルのバイト列そのまま | 「この帖のファイルはこの版でこの内容だった」 |
| 行ツリー | 25,065 | URI + `0x00` + `<seg>` の中身 | 「この URI の 1 行はこの版でこの本文だった」 |

葉に URI を混ぜるのは、主張が「**この行番号の**本文がこれ」であって
「この文字列がどこかにあった」ではないからです。区切りに `0x00` (NUL) を使うのは、
URI にも TEI の本文にも NUL が現れないので取り違えが起きないからです。

`<seg>` の中身は**テキストだけに削らず、XML のまま**取ります。25,065 行のうち
**795 行が `<lg type="waka">` を含みます** (中の `<l>` は 3,975 個。795 首 × 5 句)。
どこを和歌と同定し、どこで句を切ったかは校異の判断そのものです。
削ると「本文は同じだが同定が違う版」を区別できなくなります。

タグを含む行はこの 795 件だけで、残りの 24,270 行は素のテキストです。
つまり **32 行に 1 行は、削ると情報が落ちる**ことになります。

## 設計の判断

### RFC 6962 (Certificate Transparency) をそのまま使う

ツリーの組み方を自分で決めると、葉の数が奇数のときの扱いでほぼ必ず穴が空きます。
よくある「余った葉を複製して偶数にする」方式には、**葉の並びが違うのに同じ root に
なる**組み合わせが存在します (Bitcoin の CVE-2012-2459 と同じ穴)。
「この行はこの版に含まれていた」を証明する道具でそれが起きると、
含まれていなかった行を含まれていたことにできます。

RFC 6962 は分割位置を「n より小さい最大の 2 の冪」に固定し、複製をしません。
葉の数が 2 の冪でなくても root が一意に決まります。

葉に `0x00`、節に `0x01` を前置するのは、ある節のハッシュを葉として提出する攻撃
(second-preimage) を防ぐためです。

### SHA-256 を使う (Keccak-256 ではない)

依存ゼロとオンチェーン検証の両方を満たす選択肢がこれだけでした。
Node の `crypto` に Keccak-256 はありません (`sha3-256` は別の関数です)。
Solidity 側には SHA-256 のプリコンパイル (アドレス `0x02`、60 + 12/word ガス) が
あるので、同じ手順を両方で書けます。

### XML の正規化をしない

`ndl-witness` では JSON をキーの辞書順に並べてから digest を取っていました。
相手が **API の応答**で、同じ内容でもキーの順や空白が揺れるからです。

校異源氏物語で digest を取る相手は **git リポジトリの中のファイル**です。
すでに確定したバイト列なので揺れる余地がなく、正規化 (W3C Canonical XML) は
使いません。**正規化が必要かどうかは思想ではなく、相手が API かファイルかで決まります。**

### 「最新の root」という変数を持たない

`CorpusAnchor` はイベントを出すだけで、状態変数を 1 つも持ちません。
書ける変数が 1 つあると、それだけで過去が消せるようになります。
上書きという操作がそもそも存在しない形にしてあります。

### 25,065 件を個別に刻まない

`ndl-witness` の anchor は 1 回 27,436 ガスでした。25,065 件だと約 6.9 億ガスで、
ブロックのガス上限 3,000 万にまるで収まりません。
root 1 個なら 1 回で済み、1 行の証明は 480 バイトの経路で後から作れます。

### 包含証明は treeSize を縛らない

これはテストが落ちて初めて分かったことです。index 0 の証明では経路が全部
「右の兄弟」になり、分岐に使う値が動かないので、**treeSize が 5 でも 8 でも
計算が 1 バイトも変わりません**。包含証明が示すのは `(root, index, entry)` の
3 つ組だけで、treeSize は含まれません。

だから treeSize は証明から推測せず、**アンカーの記録から取ります**。
`anchor` が `treeSize` を必須の引数にしているのはこのためです。
`contracts/test/CorpusAnchor.t.sol` の
`test_verify_treeSizeIsNotBoundByProof_leftmostLeaf` がこの性質を固定しています。

## 256 KiB を超えるファイルの CID

`ndl-witness` の `lib/cid.mjs` は 256 KiB 以下の単一ブロックだけを扱い、
超える場合は「UnixFS の DAG が要る (この試作は未対応)」と例外を投げていました。
**校異源氏物語ではそこに当たります。** 54 帖のうち 4 帖が超えます。

| 帖 | バイト | チャンク |
|---|---|---|
| `34.xml` | 308,040 | 2 |
| `35.xml` | 309,169 | 2 |
| `47.xml` | 269,797 | 2 |
| `49.xml` | 280,752 | 2 |

そこで dag-pb の protobuf を書きました。いちばん間違えやすいのは
**PBNode が Links (フィールド 2) を Data (フィールド 1) より先に書く**ところです。
素直にフィールド番号順に並べると違う CID が出ます。

## 何がチェーンでなければならなかったのか

`05-compare.mjs` が出す表がこれです。

**壊れない (Merkle ツリーだけで足りる)**

- 1 行だけの証明を作る
- 渡す量を 645 バイトに縮める
- 受け取った側がサーバ無しで検証する
- 版が違えばどの行が違うかを突き止める

**壊れる (チェーンでしか作れない)**

- root を後から消せない
- 第三者が同じ root を独立に足せる
- 「何人が独立に同じものを見たか」が数えられる

上の 4 行は root さえ手元にあれば成り立ちます。紙に印刷した root でも成り立ちます。
**1 行の証明にチェーンは要りません。** ここを混ぜて説明すると話が壊れます。

## 永続化 — 何も送信していません

`04-permanence.mjs` は CID を**手元で計算するだけ**で IPFS に載せません。
Arweave には値段を尋ねるだけで載せません。Arweave への投入は取り消せないので、
実際に払うかどうかは別の判断として切り離してあります。

| 対象 | 大きさ | Arweave |
|---|---|---|
| TEI 本文 (`xml/master`) | 5.6 MB | 0.0674 AR ≒ ¥24 |
| サイト全体 (`docs`) | 23.7 MB | 0.2782 AR ≒ ¥100 |

(1 AR = $2.25 / $1 = ¥159.35、2026-08-25 時点。円の額は桁を見るための数字です)

**IPFS だけでは永続化になりません。** CID は「内容が同じか」を保証するだけで、
持ち続ける人がいなければ消えます。「消えない」を買うのが Arweave です。

`docs/snorql/` の SPARQL 検索は外部の Dydra を呼んでいるので、
そこが止まれば検索は動かなくなります。本文は残っても引ける状態ではなくなります。
Arweave に載せても直りません (静的化は別作業です)。

## 出発点だった 4 案

Gemini との会話で挙がった 4 つのうち、残ったのは 4 番だけです。

| | | |
|---|---|---|
| 1. 校訂履歴の信頼性担保 | 条件つき | root を刻む形で実装した。ただし公開者が自分で刻むだけでは足りない |
| 2. 分散型校正 + トークンで貢献可視化 | できない | 貢献の判定を誰がするのかが決まらない。トークンは判定を代わりにやってくれない |
| 3. 写本・異文の NFT 化 (所有権) | 半分できる | 実際に発行して測った。**Ocean は資料を NFT にしていない**。次の節 |
| 4. Web3 ストレージによる永続化 | できる | 本当の空白。¥100 で 23.7 MB が置ける |

3 について 1 つだけ新しい論点があります。校異源氏物語の底本 (池田亀鑑 1942) は
公有ですが、**TEI のマークアップ・`xml:id` の付け方・和歌の同定は中村じしんの成果**です。
NDL の所蔵資料と違い「持っていない権利を売る」形にはなりません。
それでも「所有」という枠に載せると公有の本文に値段がつくので、
希少性を資料の側ではなく**行為の側** (校訂した / 検証した / 引用した) に置く形で
なければ成り立ちません。`positioning` の発見2 の延長線上にあります。

## Ocean Protocol に載せてみた — 06-ocean.mjs

`web3/cliox` では Ocean Market のフォーク (Clio-X) を**そのまま動かしました**。
それは「他人が作ったスタックが動いた」という確認で、Ocean が中で何をしているかは
分からないままでした。ここでは **ocean.js も使わず、素の JSON-RPC で自分で組んで送ります**。
依存パッケージはゼロのままです。

相手は自分で書き写した模造品ではなく、**Ocean が Sepolia に配置した本物のバイトコード**です
(`ERC721Factory` 16,900 / `ERC721Template` 21,504 / `ERC20Template[2]` 24,017 /
`Dispenser` 6,708 バイト)。Sepolia をフォークした anvil に送るので、
**公開チェーンには何も残りません**。Ocean Market にも出していません。

### いちばん効いた発見: Ocean は資料を NFT にしていない

`positioning` の発見2 で「所有権 NFT は成り立たない」と結論を出しました。
それは**紙の上での結論**でした。実際に発行して分かったのは、
Ocean がその問題を**構造で回避している**ことです。

| | 何を表すか |
|---|---|
| ERC-721 (data NFT) | **公開者の役**。メタデータを書き換える権利と datatoken を発行する権利 |
| ERC-20 (datatoken) | **利用 1 回分の券** |

資料そのものはどちらでもありません。しかも券は**持てません**。
Ocean Market の既定テンプレート (`templateIndex 2` = `ERC20TemplateEnterprise`) は、
利用者に `buyFromDispenserAndOrder` を呼ばせ、その 1 トランザクションの中で

```
券を 1 つ出す → 注文を記録する (OrderStarted) → その場で焼く (burn)
```

をやります。3 回注文して、残高は毎回 0 に戻りました (124,132 ガス / 回)。
`totalSupply` も 0 のままです。**売買できる「持ち物」は存在せず、残るのは
「使った」という記録だけ**です。つまり Ocean が数えているのは所有ではなく利用の回数で、
これは「希少性を資料の側ではなく行為の側に置く」という上の要求とそのまま一致します。

これは仕様書を読んで気づいたことではありません。`Dispenser.dispense` を直接呼んで
`This address is not allowed to request DT` で落ち、`status()` を読んだら
渡した `0x0` ではなく datatoken 自身が入っていた、という順番で分かりました。
`createDispenser` は渡された `allowedSwapper` を**引数の名前すら付けずに捨てて**
`address(this)` を書きます。

### data NFT を図書館に渡すと何が動くか

| | 渡す前 | 渡した後 |
|---|---|---|
| 公開者のメタデータ書き換え権 | あり | なし |
| 公開者の datatoken 発行権 | あり | なし |
| 図書館のメタデータ書き換え権 | なし | あり |
| 研究者が注文できるか | できる | **できる** |
| 既に記録された注文 | 3 件 | 3 件 |

最後の 2 行が意図的な設計です。`ERC721Template.transferFrom` は全 datatoken に
`cleanFrom721()` を呼んで権限を消しますが、Enterprise 側は消す前に
「Dispenser が minter だったか」を覚えておき、消した後で minter だけ付け直します。
**管理者が代わっても配布は止まりません。** 同時に `paymentCollector` は `0x0` に戻り、
溜まっていた分は元の所有者に払い出されます。
「管理を引き継ぐ」と「配布を止める」が分かれています。

### メタデータは root を連れて行ける

1,561 バイトの DDO をそのままチェーンに書きました (220,820 ガス)。
中に帖ツリーと行ツリーの root、素材の commit、RFC 6962 の spec を入れてあります。
**「Ocean に載っている」だけでは版を固定できない**ので、root を一緒に載せます。
`ocean-node` の indexer と同じ 3 つの検査 (JSON が往復するか / hash が一致するか /
root が `01-digest` と同じか) を手元でも通しています。

`flags` の bit 1 を立てない = **暗号化しない**ので、Ocean のノードは要りません。
`did:op:583a…` という引ける名前も付きました。

### 測った値

| | |
|---|---|
| data NFT + datatoken + Dispenser を 1 回で作る | 1,362,568 ガス |
| DDO 1,561 バイトをチェーンに書く | 220,820 ガス |
| 1 回注文する (出す→記録→焼く) | 124,132 ガス |
| data NFT を移す | 234,538 ガス |

発行上限 (`cap`) は**テンプレートによって効きません**。同じ「100 回分」を渡して:

| | 読み直した cap |
|---|---|
| template 2 (Enterprise / 既定) | 100 回分 |
| template 1 (`ERC20Template`) | 2^256-1 (実質無制限) |

template 1 の `_initialize` は `// _cap = uints_[0];` をコメントアウトし、
代わりに 2^256-1 を代入します。引数は受け取るのに使われません。

### 無料なら Ocean のノードは 1 度も要らない

`_checkProviderFee` は手数料が 0 でも**必ず** `ecrecover` を呼びます。
ただし `v` が 27/28 でないとき `ecrecover` は `0x0` を返すので、
`providerFeeAddress` も `0x0` なら等しくなって検査を通ります。
つまり無料の資料は Provider の署名なしで注文できます。
有料にした瞬間、ノードの署名が必須になります。

### フォークして初めて踏んだこと (EIP-7702)

anvil の既定アカウント 10 個は、**Sepolia 上では EOA ではありません**。
10 個すべてに `0xef0100…` で始まる 23 バイトのコードが入っています。
EIP-7702 の「委任の指し札」で、後ろの 20 バイトが委任先です。
これらの秘密鍵は公開されているので、誰でも委任を刺せます (実際に刺されています)。

何が起きるか: data NFT は `_safeMint` で配られるので、相手にコードがあると
OpenZeppelin が `onERC721Received` を呼びに行き、委任先がそれを実装していないので
`ERC721: transfer to non ERC721Receiver implementer` で revert します。
フォークでない素の anvil では起きません。
`anvil_setCode` で手元のフォークの中だけコードを消してから始めています。

「公開されている鍵は公開チェーン上で他人に書き換えられている」は資金の話としては
既知ですが、**フォークして実験する側にも影響する**ことは踏むまで気づきませんでした。

## 鍵を自分で持つ — rlp / secp256k1 / tx

ここまでこの試作は **一度も鍵を持っていませんでした**。anvil に開錠済みの
アカウントを用意させ、`eth_sendTransaction` で「これを送っておいて」と頼み、
署名は anvil がやっていました (`out/deployed.json` の note にそう書いてあります)。

公開チェーンにその窓口はありません。publicnode も Infura も `eth_sendTransaction`
を持っていません (持っていたら誰でも他人の名前で送れてしまいます)。
**署名済みのバイト列を手元で組み立てて** `eth_sendRawTransaction` に渡すしかない。

依存パッケージはゼロのままにしたいので、3 つとも自分で書きました。
Keccak-256 を自分で書いたのと同じ理由です。

| | |
|---|---|
| `lib/rlp.mjs` | トランザクションの外側の符号化 |
| `lib/secp256k1.mjs` | ECDSA 署名 (RFC 6979 で k を決める) |
| `lib/tx.mjs` | EIP-1559 の 9 欄を組んで署名する |

### 間違えても「動かない」ではなく「静かにずれる」

このあたりは、間違えたときに落ちてくれません。**署名は有効なまま、送信者が
別のアドレスとして復元される**ので、「残高が足りない」と言われて終わります。
原因が署名の側にあることが見えません。踏みやすい 2 つ:

- **数の 0 は空のバイト列**であって `0x00` ではない。nonce が 0 のとき
  (＝新しい鍵の 1 回目) だけずれるので、テストが通ってから本番で落ちる
- **low-s に正規化する** (EIP-2)。`s` をひっくり返したら復元 id も反転させる。
  忘れると署名は有効なのに別人になる

### 突き合わせた相手

自前実装を信じないための工程です。`00-selftest.mjs` が 48 件に増えました。

```
RLP          仕様に載っている公開値 8 件 (0 が空になる件を含む)
ECDSA        RFC 6979 の secp256k1 公開ベクトル (秘密鍵 1 / "Satoshi Nakamoto")
鍵 → アドレス   anvil #0 の公開されている鍵 → 0xf39Fd6…92266
EIP-1559     cast mktx の出力と **バイト単位で** 7 通り
             (nonce 0 / value 0 / コントラクト作成 / 1,561 バイトの data を含む)
```

`cast` と突き合わせられるのは RFC 6979 のおかげです。k を乱数で選ぶ実装だと
毎回違う署名になるので、バイト単位の比較ができません。

### この実装の限界

**一定時間で動く実装ではありません** (not constant-time)。スカラー倍が 1 ビットずつ
分岐するので、実行時間や電力から秘密鍵のビットが漏れうる形です。
**本番の資金を持つ鍵には使わないこと。** 実用には検証済みの実装
(noble-secp256k1 など) を使ってください。ここでの目的は
「トランザクションが何でできているかを手で確かめる」ことです。

## 意図的にやっていないこと

- **IPFS / Arweave への実際の投入** — 取り消せないので、判断を分けました
- **公開チェーンへのアンカー** — ローカルの anvil で完結させています
- **本文の複製** — `out/` に置くのは digest と葉ハッシュだけです
- **Ocean Market への出品** — data NFT は発行しましたが、Sepolia を**フォークした**
  anvil の中だけです。公開チェーンには 1 バイトも送っていません。
  実物の Sepolia や本番に出すかは別の判断です
- **値段をつけること** — Dispenser は無料のままです。CC0 の本文に値段をつけると
  公有の資料を囲うことになります
- **API JSON (25,065 件) の digest** — `docs/api` は未ビルドで、
  digest を取る相手は TEI マスターにしてあります。API は TEI から生成される派生物なので、
  マスターを固定すれば足ります

## 残っている問題

- **公開者以外に刻んでもらう筋道がない。** これが最大の穴です。
  技術ではなく運用の問題で、他の研究者や図書館に「手元で `01-digest` を走らせて
  同じ root が出たら刻む」をしてもらえるかにかかっています
- **どの行が変わったかを出すスクリプトがまだない。** `out/leaves.json` に材料は
  揃っているので、2 つの版の葉ハッシュを突き合わせるだけです
- **`docs/` の静的化** — Arweave に載せても SPARQL と IIIF は動きません

## 構成

```
lib/
  sha.mjs      SHA-256 (node:crypto。25,065 葉で 5 万回以上呼ぶので同期版)
  merkle.mjs   RFC 6962 の Merkle Tree Hash と包含証明
  cid.mjs      IPFS の CID。256 KiB を超える UnixFS DAG とディレクトリも
  base.mjs     base32 (multibase 'b') と base58btc
  tei.mjs      xml/master/*.xml から <seg> を取り出す走査器
  source.mjs   素材リポジトリの場所と HEAD の commit
  abi.mjs      ABI のエンコード / デコード (cast と突き合わせ済み)
  keccak.mjs   Keccak-256 を BigInt で自前実装 (Ocean のセレクタ・EIP-55・DID に要る)
  rlp.mjs      RLP。トランザクションの外側の符号化 (仕様の公開値と突き合わせ済み)
  secp256k1.mjs ECDSA 署名を BigInt で自前実装 (RFC 6979。**一定時間ではない**)
  tx.mjs       EIP-1559 の組み立てと署名 (cast とバイト単位で突き合わせ済み)
  ocean.mjs    Ocean v4 のアドレス・型・セレクタ・DID・DDO
  chains.mjs   ローカル anvil と Sepolia フォーク
  rpc.mjs      JSON-RPC (eth_getLogs を含む)
  store.mjs    out/ の読み書き
  ui.mjs       端末表示
scripts/
  00-selftest.mjs     30 件。RFC 6962 の公開値 / IPFS の公開値 / lxml との突き合わせ
  01-digest.mjs       2 本の root を作る
  02-anchor.mjs       刻む (3 人)
  03-prove.mjs        1 行をチェーン上で検証する
  04-permanence.mjs   CID と Arweave の見積り (送信しない)
  05-compare.mjs      チェーンが要る行だけを取り出す
  06-ocean.mjs        Ocean の本物のコントラクトに発行する (フォークの中)
  dev.zsh             anvil + 配置
  ocean-fork.zsh      Sepolia をフォークした anvil
contracts/
  src/CorpusAnchor.sol       イベントだけ。誰でも呼べる。オンチェーンで RFC 6962
  test/CorpusAnchor.t.sol    27 件
```

`00-selftest.mjs` は自前の `<seg>` 走査器を当てにせず、`lxml`
(リポジトリの `build_api.py` が使っているものと同じ) の抽出結果と
25,065 件すべてを突き合わせます。`corresp` は完全一致で、本文はタグを外して
XML の実体参照を戻したうえで比べます (lxml の再直列化はソースとバイト一致しないため)。

## 隣の試作との関係

| | 何を確かめたか | 立場 |
|---|---|---|
| `did-prototype` (案A) | 署名で主張と版を固定する | 記録を作る人 = 記録される対象 → 行き止まり |
| `evm-provenance` | 追記だけの来歴。削除関数がどこにも無い | — |
| `jpyc-access` (案C) | **非公開**資料。支払いと機関の許諾 | 機関が門番 |
| `ndl-witness` | **公開**資料。チェーンは門番でなく証人 | 中村は第三者 (観測者) |

| `genji-witness` (これ) | **自分の公開物**。1 行の粒度で版を証明する。Ocean には**自分で組んで**送った | 中村は公開者 → 案A に戻る |

## 秘密情報

このアプリはローカルの anvil だけで完結するので、既定では秘密情報を使いません。
`scripts/dev.zsh` が使う anvil の既定アカウントは**公開されている値**です。
署名は anvil 側で行うので、**秘密鍵をファイルに書きません** (`out/deployed.json` に
入るのはアドレスだけです)。

公開テストネットに出す段になったら、鍵は `.env.local` に `op://` 参照だけを書き、
`op run` で注入します。
