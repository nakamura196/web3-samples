# zk-shor

ゼロ知識証明を自分で実装し、それを Shor のアルゴリズムで破るところまでを
1つに収めた**教材**。実運用の暗号ライブラリとして使ってはいけない。

```
zkshor all
```

## 何をやっているか

**ZKP (ゼロ知識証明)** — 「秘密 x を知っている」ことを、x を一切渡さずに
証明する手続き。ここでは最小の実物である **Schnorr 証明** を実装する。
公開されるのは `y = g^x` だけで、x は出ない。デジタル署名も
zk-rollup も、根っこはこれである。

**Shor のアルゴリズム** — 量子計算機で素因数分解と離散対数を多項式時間で
解く。1994 年に公開された。`y` から `x` を直接計算してしまう。

この2つを並べると何が起きるか。**プロトコルは無傷のまま、仮定だけが壊れる。**
Schnorr の3つの性質のうち、完全性もゼロ知識性も生き残る。死ぬのは
「x を知らない者は通せない」という健全性の *前提* だけである。証明は
相変わらず検証を通り、しかし誰でも作れる。

## 実行結果 (抜粋)

```
$ zkshor shor --peaks

[shor] 群: toy-10: |q| = 10 bit, |p| = 22 bit, q = 827
[shor] 状態ベクトル: 827 x 827 = 683929 振幅 (10.4 MiB)
[shor] 実機なら約 30 論理量子ビット相当
[shot 1] 第3レジスタを測定 -> f = 446999; 残った基底 827 個
[shot 1] QFT 後に測定 -> (c, d) = (436, 661)
[shot 1] x = d * c^-1 mod q = 11
[shot 1] 検証: g^11 == y  -> 成功

復元した x = 11   本物の x = 11   一致: True
測定 1 回 / 0.07 秒
d == c*x mod q が厳密に成立: True

直線 d = c*x 上の確率合計 : 1.000000000000
直線から外れた確率の合計   : 1.976e-14
外れた最大の確率           : 2.407e-35
確率が非ゼロな格子点        : 827 / 683929
```

最後の2行が要点。「たまたま当たった」のではなく、QFT の干渉が
**傾き x 以外の可能性を全部打ち消している**。だから測定 1 回で秘密鍵が出る。

| `src/zkshor/shor_factor.py` | Shor の素因数分解版。玩具 RSA を壊す |
| `src/zkshor/ledger.py` | 台帳モデル。harvest now, forge later |
| `src/zkshor/estimate.py` | 本番サイズの費用見積り |

## コマンド

```
zkshor zkp         2048 bit / 256 bit の実サイズで Schnorr を組み、3性質を確認
zkshor classical   nonce 再利用 / bsgs / rho で玩具の鍵を破る
zkshor shor        Shor の離散対数で秘密鍵を取り出し、偽の証明を通す
zkshor factor      Shor の素因数分解で玩具 RSA の秘密指数を再構成する
zkshor ledger      台帳から公開鍵を収穫し、20XX 年に偽の送金を通す
zkshor estimate    「では本番サイズは？」に数字で答える
zkshor all         全部順に流す
```

## Schnorr の3つの性質と、それを示すコード

ゼロ知識証明と呼べるには3つ揃う必要がある。このリポジトリでは、
どれも **文章ではなく関数**で示している。

| 性質 | 意味 | 対応するコード |
|---|---|---|
| 完全性 | 正直な証明は必ず通る | `prove` / `verify` |
| 健全性 | 知らない人は通せない | `extract` — 2本の transcript から x が出る |
| ゼロ知識 | 通った証明から x は漏れない | `simulate` — 秘密なしで本物と同分布の証明を作る |

`extract` が書けることが健全性の証明であり、`simulate` が書けることが
ゼロ知識性の証明である。そして `extract` は、そのまま **nonce 再利用への
攻撃コード**でもある (PS3 の ECDSA 事故、2013 年の Bitcoin 鍵流出)。
守りの証明と攻めの実装が同じ式になるのは偶然ではない。

## 破り方の階層

| 手口 | 計算量 | 玩具 (q=10bit) | 本番 (q=256bit) | 性質 |
|---|---|---|---|---|
| nonce 再利用 | O(1) | 1 演算 | 1 演算 | 実装のバグ |
| baby-step giant-step | O(√q) | 35 演算 | 2^128 演算 | 数学どおり |
| Pollard rho | O(√q) 時間・O(1) 領域 | 69 演算 | 2^128 演算 | 数学どおり |
| **Shor (離散対数)** | **多項式** | **測定 1 回** | **測定 1 回** | **仮定の崩壊** |

古典の攻撃は q を大きくすれば逃げ切れる。だから今日の Schnorr / ECDSA は
安全と言える。Shor は逃げ切れない。q を倍にしても量子側の費用は
多項式でしか増えない。

## ブロックチェーンとの関係

XRPL の署名は secp256k1 か Ed25519、Ethereum は secp256k1。
どれもここで壊した「離散対数が難しい」という**同じ一行**に乗っている。

`zkshor ledger` はこれを台帳モデルで再現する。

1. アドレスは公開鍵のハッシュなので、鍵は**初回送金までは**隠れている
2. 一度送金すると、公開鍵は台帳に載り**永久に消えない**
3. 攻撃者は今日の台帳を保存しておくだけでよい (権限も侵入も不要)
4. 量子計算機が手に入った日に鍵を再構成し、偽の送金を通す

厄介なのは、この取引が**台帳の検証規則から見て完全に正当**であることだ。
署名は正しく、アドレスも一致し、二重支払いでもない。不正の痕跡が
どこにも残らないので、後から無効化する根拠がない。

そして「保存されているほど危ない」という性質は、台帳の長所と
まったく同じものである。ここが、アーカイブの立場から見て一番効く。

詳細は [`docs/why-archives-care.md`](docs/why-archives-care.md)。

## 安全性について — 「破れるなら、まずいのでは？」

まずくない。理由は3つ。

1. **破れるのは玩具パラメータだけ。** q は 10 bit (約 1000)。この大きさなら
   Shor を使わずとも baby-step giant-step が 35 演算で解く。デモが新しく
   暴くものは何もない
2. **シミュレータは指数的に重い。** 状態ベクトルは q² 個の複素数。実運用の
   256 bit にすると 10^155 バイト。観測可能宇宙の原子数 (10^80) を
   10^75 倍上回る。実鍵には物理的に届かない
3. **Shor は 1994 年の公知のアルゴリズム。** 秘密の武器ではない

破るのはその場で生成した自分の鍵だけ。ネットワークには一切触らない。

`shor_dlog()` は p が 62 bit を超えると **明示的に例外を投げて拒否する**。
「うっかり本番パラメータを渡す」経路を塞いである。

## 本番サイズの見積り

`zkshor estimate` の出力。2つの数字を混同しないこと。

| q のビット長 | 用途 | 古典シミュレーションの状態量 | 論理量子ビット |
|---|---|---|---|
| 10 | このデモ | 16 MiB | 40 |
| 16 | このデモ (上限付近) | 64 GiB | 58 |
| 160 | 旧 DSA / SHA-1 世代 | 10^98 バイト | 490 |
| 256 | secp256k1 / Ed25519 / XRPL | 10^155 バイト | 778 |
| 521 | P-521 | 10^315 バイト | 1573 |

左の列 (古典シミュレーション) は**永遠に不可能**。
右の列 (量子実機) は**ハードウェア次第でいつか可能**。
デモが玩具サイズなのは左の制約であって、右の困難さを意味しない。

公表されている実機の見積り:

- Gidney & Ekerå 2021 — RSA-2048 を 8 時間 / 物理 2000 万量子ビット
- Ekerå & Håstad 2017 — 離散対数は素因数分解より**安い**
- 2026 年時点の実機は、誤り訂正込みの論理量子ビットで 100 個程度の桁

## 実装上の落とし穴 (作りながら踏んだもの)

- **QFT を行列で書くと死ぬ。** N = 2^18 の QFT 行列は 1 TB を要求する。
  FFT で掛ける (近似ではなく厳密に同じ線形写像)
- **連分数の漸化式の初期値。** `h_(-1)=1, h_(-2)=0` / `k_(-1)=0, k_(-2)=1`。
  ここを間違えると分母が常に 1 になり、周期が一生取れない
- **Fiat-Shamir のハッシュに `y` と群パラメータを入れる。** `t` だけを
  ハッシュすると、証明を別の鍵の証明として使い回せる
- **連結する値は長さ前置き。** `H(a||b)` の境界が曖昧だと別々の主張が
  同じハッシュになる
- **群の元であることを検証する。** `contains()` を省くと small-subgroup 攻撃が通る
- **`gcd(a,N)>1` を引いたら引き直す。** 古典で解けてしまうので Shor の
  デモにならない
