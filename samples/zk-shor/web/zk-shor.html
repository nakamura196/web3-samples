00

ふたつの言葉

ゼロ知識証明は、「秘密の数 x を知っている」ことを、x を一切渡さずに 相手に納得させる手続きです。公開されるのは y = gx だけ。 デジタル署名も、暗号通貨の zk-rollup も、根はこれひとつです。

Shor のアルゴリズムは、量子計算機が y から x を 直接計算してしまう手順です。1994 年に公開されました。

並べると何が起きるか。手続きは無傷のまま、前提だけが崩れます。 証明は相変わらず検証を通り、しかし誰にでも作れるものになる。 以下はその過程を、玩具サイズの鍵で最初から最後まで通したものです。

安全性について。ここで破る鍵は q が 8 ビット前後、つまり数百通りしかありません。 量子計算を持ち出さなくても総当たりで解けます。実運用の 256 ビット鍵をこの方式で シミュレートするには 10155 バイトのメモリが要ります —— 観測可能な宇宙の原子数の 1075 倍です。実際の鍵には決して届きません。

完全性

正直に作った証明は必ず通る。

健全性

x を知らない者は通せない。——これが今から壊れます。

ゼロ知識

通った証明から x は漏れない。「秘密なしで作る」を押すと、 x を持たずに検証を通る記録が作れます。本物と分布が完全に一致するので、 見た人が得る情報はゼロです。

03

量子計算機で解く

Shor が見ているのは、2 変数の関数 f(a,b) = ga·yb mod p です。 y = gx なので f は a + x·b だけで決まる。 同じ値をとる格子点は直線に並び、その直線の傾きがそのまま秘密の x です。

左の板がその値の場です。縞が見えるはずですが、縞の間隔から傾きを読むには 古典計算機だと平方根の手数がかかる。量子計算機は重ね合わせで全点を同時に評価し、 フーリエ変換で傾きだけを取り出します。

04

台帳を偽造する

XRP Ledger の署名は secp256k1 か Ed25519、Ethereum は secp256k1。 どれもいま壊した「離散対数は難しい」という同じ一行に乗っています。

台帳のアドレスは公開鍵のハッシュなので、鍵は初回送金までは隠れています。 しかし一度送金すれば、公開鍵は台帳に載り、二度と消えない。 攻撃者がすべきことは待つことだけです。

harvest now, forge later
先に鍵を生成してください。
偽造された送金は、台帳の検証規則から見て完全に正当です。 署名は正しく、アドレスも一致し、二重支払いでもない。不正の痕跡が残らないので、 あとから無効化する根拠がありません。

06

記録を残す側から見ると

紙の記録が証拠になるのは、来歴・保管の連鎖・第三者の証言という 独立した複数の根拠が重なるからです。どれかが崩れても全体は残る。

電子署名はそうなっていません。「本人が承認した」という主張は、最終的に たった一行の数学的仮定に載っています。そして仮定が崩れるとき、 過去に作られた署名も一緒に崩れます。切れ目がない。 2026 年の署名は 2050 年に検証しても通り、しかしその頃には 2050 年の誰かが 同じものを作れる。検証する側から、この 2 つは区別できません。

長期保存の営みそのものが、将来の攻撃材料を育てるという構造もあります。 改竄検知のために台帳を保存すれば、同時に公開鍵の一覧を保存していることになる。

だから手当ては、暗号の中だけでは閉じません。

耐量子署名に移る

NIST FIPS 204 / 205。とくに SLH-DSA はハッシュだけに依存するので Shor が効きません。

重ねる

従来署名と耐量子署名を両方付ける。移行期はこれが現実的です。

時刻を独立に固定する

署名が壊れても「壊れる前に存在した」は残せます。

証拠をひとつの仮定に賭けない

署名、来歴、第三者保管、公開の記録。紙の時代からの標準的な手当てに戻ります。
